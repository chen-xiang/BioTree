# BioTree 页面加载与显示性能

在动物界、植物界近乎完整覆盖（可达百万级节点）的前提下，保证浏览与管理可用的性能约定。与 [DATA_STORAGE.md](./DATA_STORAGE.md)、[TECH_STACK.md](./TECH_STACK.md) 配套。

**本期不引入 Redis。** 性能首先靠访问模式与查询设计，而不是缓存中间件。

---

## 1. 核心原则

**永不一次拉取或渲染整棵分类树。**

页面只消费：

- 当前节点的 **一页直接子节点**，或
- **一条** 详情（含当前语言内容），或
- **一页** 搜索结果。

手段归纳：**按需加载 + 接口变瘦 + 数据库索引 + 列表虚拟滚动**。

---

## 2. API 约定

| 场景 | 要求 |
| --- | --- |
| 分类树 | **懒加载**：仅 `GET .../taxa/{id}/children`（或根节点 children） |
| 根层 | 只返回界（或产品约定的顶层），数量极少 |
| 详情 | 单次只取一个 taxon + **当前** `locale` 的 i18n + 少量 media 元数据 |
| 搜索 | 独立搜索 API，**分页**；MySQL 优先 **FULLTEXT**，否则前缀再含糊 LIKE；覆盖俗名与**异名** |
| 子节点很多 | children **分页**；前端「加载更多」+ 子节点虚拟列表 |
| locale | 列表/详情俗名与介绍：请求语言 → 英语 → 学名 |
| 公开缓存 | 只读 `/api/taxa/**` 可配置短 TTL `Cache-Control`（`app.cache.public-max-age-seconds`） |
| 「所有后代」统计/导出 | 异步或管理端任务，禁止同步堵在页面请求 |
| `view=simple` | 子节点通过冗余列 `simple_parent_id`（最近林奈七级祖先）索引查询；导入/写路径维护；启动时对旧数据可回填 |

**列表 / children 仅包含瘦字段**，例如：

- `id`
- `rank`
- `scientificName`
- `commonName`（当前 locale 回退链）
- `childCount`（**相对当前 view** 的可见子节点数）
- `directChildCount`（物理直接子节点数）
- `hasChildren`（相对当前 view）
- `rankRaw`（可选）

**禁止**在树/列表接口中返回：

- 详细介绍全文
- 全部语言的 i18n
- 大图完整列表（或仅返回首图缩略信息且仍须克制）

详情接口再取 `summary` / `description`、媒体列表等。

---

## 3. 前端约定

| 项 | 要求 |
| --- | --- |
| 树 | 展开节点时才请求 children；可缓存已展开层，但不得预拉整树 |
| 长列表 | **虚拟滚动**，只渲染可视区域 |
| 图片 | `loading="lazy"`；列表用缩略图，详情再加载大图 |
| 路由 | 详情独立页或面板；离开时取消未完成请求 |
| 语言 / 主题切换 | 只重取 **当前页** 内容语言；不要为换语言重载整树 |
| 默认交互 | 优先 **搜索** 或 **逐级下钻**，避免一打开就深展到种 |
| 面包屑 | 依赖后端路径/祖先信息跳转，而非同屏堆多列整层数据 |

动效与设计系统复用仍须遵守 [CODING_RULES.md](./CODING_RULES.md)，但动画不得阻塞数据加载或造成额外全量请求。

## 4. 数据库与查询

### 4.1 索引与冗余（与存储文档一致）

| 访问模式 | 手段 |
| --- | --- |
| 按父节点拉子节点 | `INDEX(parent_id, …)` |
| `view=simple` 子节点 | `INDEX(simple_parent_id)` + 林奈七级 `rank` 过滤 |
| 学名搜索 | `scientific_name` 索引（或前缀/全文策略按实现选定） |
| 俗名搜索 | `taxon_i18n(locale, common_name)` 相关索引 |
| 详情 | 主键查询 |
| 面包屑 / 祖先链 | `materialized_path`（或闭包表）；避免每次深层递归 CTE 作为唯一方案 |
| 是否有子节点 | 冗余 `child_count`，减少频繁 `COUNT(*)` |

长介绍仅存在 `taxon_i18n.description`，**仅详情查询 SELECT**；列表禁止 `SELECT *`。

### 4.2 写入时维护

- 增删改子节点时维护父节点 `child_count`。
- 移动节点时更新自身及子孙的 `materialized_path`（须有测试覆盖）。

## 5. 无 Redis 时的缓存策略

优先把 §2–§4 做对。仍不足时，在不引入 Redis 的前提下可考虑：

| 手段 | 说明 |
| --- | --- |
| HTTP 缓存 | 公开只读 children/详情可短 TTL（`Cache-Control`）；写操作后依赖短过期 |
| 进程内极小缓存 | 仅缓存界/门等极少变高层（多实例会不一致；单机可接受） |
| 搜索升级 | 量过大时二期再引入专用搜索引擎；首期 MySQL + 分页 |

管理端写接口与带 Cookie 的 Session 请求不要做与公开页相同的长缓存。

---

## 6. 配图与多语言内容性能

| 点 | 做法 |
| --- | --- |
| 多语言 | 详情带 `locale`，只查 **一行** i18n |
| 介绍 | 列表用 `common_name`；详情用 `summary` + `description`（可一次返回，仍是单行） |
| 图 | 元数据可分页；浏览器尽量直连 Local 受控 URL 或 OSS；避免 Java 整文件读入再转发 |

---

## 7. 性能预算（设计目标）

| 操作 | 目标 |
| --- | --- |
| 展开一层 children | 同区域网络下百毫秒量级；payload 控制在几十 KB 量级 |
| 打开详情 | 主键 + 单条 i18n + 少量 media，避免大 JOIN 撑爆结果集 |
| 首屏 | 只加载应用壳 + 根层节点；**不**下载整库 |

具体数值可在联调后写入基准测试，但不改变「禁止整树下发」的硬约束。

---

## 8. 一句话

**数据可以全在 MySQL，页面永远只吃当前一页孩子 / 一条详情 / 一页搜索；懒加载、虚拟滚动、列表与详情字段分离、路径字段加速面包屑——优先于引入 Redis。**
