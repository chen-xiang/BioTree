# BioTree 基础开发规范

本文档为项目基础 Rule。实现与评审时均应遵守；与 Cursor Agent 规则（`.cursor/rules/`）保持一致。

---

## 1. 文件头

生成代码须带**完整文件头**，包含：简述、`Author: chen-xiang`、创建/更新日期。

### 1.1 新建文件

只写 `Created: YYYY-MM-DD`，不写 `Updated`。

**Java 示例：**

```java
/**
 * 分类单元领域实体，表示界门纲目科属种中的一个节点。
 *
 * Author: chen-xiang
 * Created: 2026-08-31
 */
```

**TypeScript / Vue 示例：**

```ts
/**
 * 分类树 Pinia Store：缓存公开浏览用的子树数据。
 *
 * Author: chen-xiang
 * Created: 2026-08-31
 */
```

**Vue SFC：** 文件头写在 `<script>` 顶部或文件最上方的块注释中（与项目后续模板保持一致）。

### 1.2 实质修改

每次**实质修改**（行为、结构、契约、样式语义变更；纯格式化/重命名除外）在文件头下方**追加**一行：

```text
Updated: YYYY-MM-DD 一句中文说明
```

可累积多行 `Updated`，按时间从上到下追加。`scripts/*.bat` / `*.sh` 的说明用**英文**（见第 2 节）。

**示例：**

```java
/**
 * 分类单元领域实体，表示界门纲目科属种中的一个节点。
 *
 * Author: chen-xiang
 * Created: 2026-08-31
 * Updated: 2026-09-12 增加接受名（isAccepted）字段
 * Updated: 2026-10-03 父节点关联改为懒加载
 */
```

## 2. 注释与日志语言

| 类型 | 语言 |
| --- | --- |
| 代码注释（含 JavaDoc / TSDoc、行内注释） | **简体中文** |
| 仓库脚本（`scripts/*.bat` / `*.sh` 的注释与输出） | **英文** |
| 日志文案（`log.info` / `console` 用于诊断的消息等） | **英文** |

说明：

- 用户可见的 UI 文案走 **vue-i18n**，不写死某一种语言。
- 异常信息若面向 API 调用方：业务 `message` 可按 API 约定；**日志**仍用英文记录原因与上下文。
- Windows `cmd` 按系统代码页解析 `.bat`，UTF-8 中文 `rem` 会被拆成伪命令；脚本一律英文以免乱码。

## 3. 测试

- 功能须有**完整测试用例**（后端单测/切片测；前端关键逻辑与组件测按模块补齐）。
- **实现变更时，测试必须同步**：新增覆盖、修复失败用例，禁止长期红灯或「先合后补」。
- 层级校验、权限（公开 vs 管理端）、存储策略切换等核心规则为必测重点。

---

## 4. 设计原则

| 原则 | 要求 |
| --- | --- |
| 高内聚、低耦合 | 按领域/用例拆分；存储、安全、API 边界清晰；避免交叉依赖 |
| 少魔鬼数字 | 层级、限制、超时、状态码等用命名常量或枚举 |
| 信任域内不过度防御 | 已在边界校验过的入参，域内勿层层重复 null/格式检查；对外边界（Controller、反序列化、上传）严格校验 |

---

## 5. 前端界面与体验

- **响应式**：桌面与移动可用，布局不断裂、不遮挡关键操作。
- **深浅模式**：语义色走设计 Token，禁止写死仅适配某一主题的颜色。
- **多语言**：可见文案走 vue-i18n；学名等拉丁文可按产品约定不翻译。
- **一致性**：交互模式与视觉层级统一；优先**复用设计系统组件**。
- **Token 化、组件化**：颜色、字号、间距、动效时长等进 Token；页面组合组件而非复制样式。
- **美观精致**：留白、对齐、层级清楚；避免粗糙堆砌。
- **动效**：关键状态变化（展开树、路由切换、反馈、主题切换等）应有克制、有意义的过渡，不堆无意义动画。

---

## 6. 变更策略

- **默认不保留旧实现**。
- **不做 deprecated 过渡**：直接替换调用方与实现，不留双轨 API/死代码「兼容期」（除非产品明确要求且文档单独说明）。
